Step 0 checklist — use the existing firmware first

  1. Only one application can use the COM port. Release it from other monitors before connecting. You can compare status uptime entirely within this page.
  2. Open this HTML file in desktop Chrome or Edge. Check the two capability values above. If disk access is blocked, serve this folder on localhost and open the page there.
  3. For the tested board, select explicit DTR=true, RTS=false. Click Connect, choose the companion, and send status. Save whether uptime restarted or new boot output appeared. The first page connection has no automatic pre-open reference.
  4. Click Disconnect and keep USB plugged in. Check that the board still works, reconnect here, and send status again. Compare uptime for a reset.
  5. For a new setup, repeat five times, including during Live. Compare driver defaults and explicit DTR/RTS settings only as a deliberate diagnostic test. Settings are locked while connected; disconnect before changing them.

JP's 2026-09-15 bench result: explicit DTR=true, RTS=false passed repeated connections and Live. Driver defaults caused a reset on disconnect; closing the VS Code monitor caused an unresolved freeze. Use the tested explicit settings on this setup.
